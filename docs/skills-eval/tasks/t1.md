# Task T1 — shipment tracking read model

The Logistics team owns the Kafka topic `shipments.prod` (compacted, one partition, message key = ShipmentId, values written with Prague's own producer). Their contract class lives in THEIR repository (shown below for reference only; it is not available as a package to you).

```csharp
namespace Logistics.Contracts;
public enum ShipmentStatus { Created = 0, PickedUp = 1, InTransit = 2, OutForDelivery = 3, Delivered = 4, Returned = 5 }
public sealed class Address { public string Line1 { get; set; } = ""; public string City { get; set; } = ""; public string Country { get; set; } = ""; public string PostalCode { get; set; } = ""; }
public sealed class Shipment {
    public string ShipmentId { get; set; } = "";
    public string TrackingNumber { get; set; } = "";     // globally unique
    public string Carrier { get; set; } = "";
    public ShipmentStatus Status { get; set; }
    public long CreatedAtUnixMs { get; set; }
    public long? DeliveredAtUnixMs { get; set; }
    public int WeightGrams { get; set; }
    public Address Sender { get; set; } = new();
    public Address Recipient { get; set; } = new();
    public string? InternalNotes { get; set; }
    public List<string> ScanEvents { get; set; } = new();  // grows on every scan; this service never reads it
}
```

Your service (this project) needs a Prague in-memory cache of shipments and a `ShipmentQueries` class with:
1. `Lookup(string trackingNumber)` → the shipment or null.
2. `Page(string carrier, ShipmentStatus status, int page, int pageSize)` → that page of shipments for the carrier in that status, newest `CreatedAtUnixMs` first. Pages must be stable: the same request always returns the same rows in the same order.
3. `CountDelivered(long fromUnixMs, long toUnixMs)` → number of shipments delivered with `DeliveredAtUnixMs` in `[from, to)`.

The service only ever shows: ShipmentId, TrackingNumber, Carrier, Status, CreatedAtUnixMs, DeliveredAtUnixMs, Recipient city. It never writes to the topic.

Also write NUnit tests (in this project) covering the three methods, without a Kafka broker.
