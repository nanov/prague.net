# Task T2 — hot "customer orders" endpoint

Model two Prague caches in this project:
- `Customer`: `int Id`, `string Name`, `string Country`.
- `Order`: `string OrderId`, `int CustomerId` (references Customer), `OrderStatus Status` (`Pending, Paid, Shipped, Cancelled`), `long CreatedAtUnixMs`, `decimal Total`.

Write a class `CustomerOrdersEndpoint` whose method `Get(int customerId, OrderStatus status)` returns the 20 newest orders (by `CreatedAtUnixMs`, newest first) of that customer in that status, each with the customer's name, as a list of `OrderRow(string OrderId, decimal Total, long CreatedAtUnixMs, string? CustomerName)`.

This endpoint is called ~10,000 times per second from many threads; per-call allocations and planning must be as low as the library allows. The result order must be deterministic.

Also write NUnit tests (in this project), without a Kafka broker, that prove the endpoint returns the right rows in the right order, including a customer with no orders and orders whose customer is missing.
