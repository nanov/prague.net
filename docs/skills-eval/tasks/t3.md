# Task T3 — Kafka wiring, filtering and a live projection

Model a Prague cache `Order`: `string OrderId` (key), `int CustomerId`, `OrderStatus Status` (`Pending, Paid, Shipped, Cancelled`), `decimal Total`. It is fed from the compacted topic `orders.<env>` where `<env>` comes from configuration.

Write the registration code (a static method `Register(IServiceCollection services, string bootstrapServers, string env)`) so that:
1. Only messages whose Kafka header `tenant` equals `"acme"` are accepted.
2. An order whose `Status` becomes `Cancelled` must disappear from the cache (the producer never sends tombstones for cancellations, it just re-sends the order with Status = Cancelled).
3. A projection `OpenTotals` keeps, per CustomerId, the sum of `Total` over orders that are `Pending` or `Paid`, up to date as messages arrive. Other code reads `OpenTotals.Get(customerId)` from request threads at any time. The projection must also be correct for the data that was already in the topic when the service started.
4. A background job logs the number of `Pending` orders once a minute, but must not start before the caches have loaded.

Also write NUnit tests (in this project), without a Kafka broker, for the projection logic.
